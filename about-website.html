About this website

This site was generated by Portrox — a self-hostable, multi-tenant portfolio engine.

This is a locked system page. Site owners cannot edit or delete it. It ships with Portrox itself, not with your content folder, and the database exposes it read-only.

What Portrox is

Portrox is two applications in one repository:

  1. Portrox Studio — a private admin dashboard that runs on your own machine, bound to 127.0.0.1 with a kernel-assigned dynamic port. It never listens on a public interface.
  2. The public portfolio — a fast, fully static website published to GitHub Pages over HTTPS. No server and no database are required to serve it, and there are no runtime CDN dependencies.

You enter your credentials in the Studio. You edit content. Portrox renders static HTML and CSS. You publish. That is the whole loop.

Capabilities

  • UI-only configuration — Supabase and GitHub credentials are entered in the Studio, never in a shell.
  • Multi-site — manage many independent portfolios from one Studio.
  • Auto-provisioning — the Studio creates the GitHub repository and configures Pages for you.
  • Dual-mode intro — write Markdown, or answer a guided questionnaire.
  • Upwork-class profile — availability badge, rate, overview, skills, work history, filterable portfolio.
  • Services and payment links — publish tiers with checkout links.

  • Inbox — contact and booking requests in one place.
  • Tenant isolation — Postgres Row Level Security separates every site's data.

User guide

1. Install

git clone https://github.com/sid200ok/portrox.git
cd portrox
npm link
portrox start

portrox start prints the exact local URL, for example http://127.0.0.1:45515. The port is chosen by the operating system on every start. Nothing is hardcoded.

2. Configure from the UI

Open the Studio URL. In Setup:

  1. Supabase — paste your Project URL and publishable key, then sign in with your Supabase Auth email and password. This establishes you as the site owner.
  2. GitHub — paste a Personal Access Token with repo and workflow scope. The Studio validates it and shows the resolved account.

Credentials are written to ~/.portrox/config.json with mode 0600. Passwords are never stored. Tokens are never sent back to the browser.

3. Create and publish a site

In Sites, enter a name and choose a mode, then Create. Per site:

  1. Build — render static output and preview it locally.
  2. Register — create the tenant row in Supabase under your owner id.
  3. Publish — provision the GitHub repository, push the rendered output, configure Pages, and mark the site live.

4. Everyday commands

portrox status
portrox restart
portrox logs
portrox stop
portrox enable-autostart
portrox disable-autostart
portrox doctor

GitHub Pages reality

One account has exactly one {account}.github.io user site.

| Mode | URL | Limit |

|---|---|---|

| user | account.github.io | 1 per account |

| project | account.github.io/repo | unlimited |

| org | org.github.io | 1 per org |

| custom | your domain | unlimited (needs DNS) |

Security model

  • The Studio binds only to 127.0.0.1; the kernel assigns a free port each start.
  • ~/.portrox is 0700; config.json and state.json are 0600.
  • Every write requires a valid Host, a loopback Origin when present, and a per-run CSRF token.
  • portrox stop verifies process ownership before signalling. It never mass-kills processes.
  • Publishable Supabase keys are public by design and protected by Row Level Security.
  • Secret keys never enter a generated site. The renderer refuses to build if one is detected.
  • Anonymous visitors have no direct table write; a rate-limited SECURITY DEFINER RPC is the only intake path.
